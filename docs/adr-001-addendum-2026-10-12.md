# ADR-001 — Addendum: what the implementation actually proved (2026-10-12)

The original ADR selected Supabase Free and documented Aiven Free as the
fallback. The implementation work that followed produced evidence the ADR
now has to carry, including two corrections to what it implied.

## What the backup implementation proved

* **The archive strategy is now single and explicit everywhere**: the
  artifact is the PostgreSQL custom-format dump itself (`--format=custom`,
  which libpq compresses), with no outer gzip layer. The earlier revision
  wrapped its dump in gzip and handed the result to `pg_restore`, which
  refuses it — so the "verification" could never have restored anything.
  `scripts/restore_drill.py` asserts the negative case against a real
  PostgreSQL: a gzip-wrapped archive is refused, an unwrapped one is
  accepted.
* **A backup is only claimed when it has been restored.**
  `backend/scripts/pg_backup.py` now takes `--verify-restore-into` and
  restores the dump into an empty non-production target *before* the
  artifact is written, recording the target identity and table row counts
  in the manifest as `restore_verification`. A production source is
  refused without one. The old `--no-verify` flag is gone: an unverified
  backup is a refusal, not a state.
* **The restore drill passed on real PostgreSQL** — run
  `38234553521` of `restore-drill.yml`, with all four negative cases
  refusing (gzip-wrapped archive, corrupted artifact, wrong passphrase,
  non-empty restore target) and the plaintext dump removed from the runner.
  Its evidence: source 3 seeded rows → restore verification 3 rows →
  independent second restore 3 rows, artifact SHA-256
  `8d891ba76902d7196a3173678793beaa037890215568a2587ba998cd6da85e4b`.
  This proves the *procedure*; it is not evidence about production data.
* **Three real defects were found by the real run, not by review**: a
  missing `cwd` in the drill's subprocess helper; the restore verification
  resolving SQLAlchemy's uninstalled psycopg2 dialect (fixed by routing
  every engine through one `app.database.engine_for` factory that applies
  the repository's psycopg3 rewrite and TLS policy); and a SQLite-ism
  (`is_archived = 0`) in the restore verification's visibility predicate
  that PostgreSQL rejects as `boolean = integer` (now `NOT is_archived`,
  which means the same on both dialects).

## Corrections to the ADR's Supabase reasoning

1. **The keep-alive is not an availability guarantee.** Supabase's own
   pricing page states Free projects are *paused after 1 week of
   inactivity*, and nothing the repository runs can override a provider's
   plan policy. The weekly read-only keep-alive reduces the chance of a
   pause; it cannot promise uptime. The architecture therefore treats an
   unavailable database as a **normal, supported state** — the public
   catalogue serves from the committed static snapshot, the API reports
   honest errors — rather than promising a policy it cannot enforce. If the
   operator needs an always-on database, that is a paid plan and it is
   their decision, not something this repository should assume.
2. **A production backup is an authorized action, not a default.**
   `SZ_BACKUP_PRODUCTION_AUTHORIZATION` records who approved it and when;
   classification is by host policy, not by a name containing "prod" (the
   audited production host contains no such substring and the old
   substring guard admitted it). A production backup additionally requires
   a restore target. Every manifest records the source class, the
   authorization, and whether the artifact was restored — so no workflow's
   green checkmark can be read as "production is backed up" when it is not.

## The unresolved reality, unchanged

Neon production remains quota-blocked (provider error: "Your account or
project has exceeded the quota"), no production backup exists, and
therefore no production migration parity. The cutover gate in the ADR is
unchanged: real production data recovered and validated, parity proven on
the target, the target backed up and restored, features verified, rollback
documented, and explicit operator approval.
